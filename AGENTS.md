# Materializr (форк под планшет) — правила для исполнителя

Ты — исполнитель. Задачи ставит и принимает куратор (Claude). Делай ровно то, что в ТЗ
(`tasks/<файл>.md`); если ТЗ неясно или противоречит коду/API — не выдумывай, напиши в отчёте.

## Проект
- C++17, CMake. Геометрия — OpenCASCADE 7.9 (`src/core`, `src/modeling`), интерфейс — Dear ImGui
  (docking) (`src/ui`, `src/app`), окно/ввод — SDL3, графика — OpenGL 3.3 (десктоп) / GLES 3.0 (Android).
- Android: `android/` (Gradle + NDK), точка входа `src/android_main.cpp`. Один исходный код на все платформы.
- Функции оформлены плагинами: `src/plugins/*Plugin.cpp`.
- Тач-режим: `src/touch_mode.h` (`touchMode()`), масштаб интерфейса: `src/ui_scale.h`.

## Обязательные правила кода
1. **Десктоп не ломать.** Код только для Android — под `#if defined(__ANDROID__)`; для мобильных
   платформ вообще — `MZ_MOBILE` (`src/platform_defs.h`). Тач-поведение — по `touchMode()`, а не по платформе.
2. **Не выдумывай API.** Имена функций ImGui, SDL3, OpenCASCADE, GLES бери из уже существующего кода
   проекта (поиском по `src/`) или из заголовков. Не нашёл — напиши в отчёте, не угадывай.
3. **Размеры на экране — в dp, не в пикселях:** умножай на масштаб из `ui_scale.h` так же, как
   соседний код. Толщины линий, радиусы точек, зоны касания — тоже.
4. Не меняй то, чего нет в ТЗ: никаких попутных рефакторингов, переименований, форматирования чужого кода.
5. Стиль — как в окружающем коде (отступы 4 пробела, `namespace materializr`). Комментарии — на
   английском, коротко и по делу. Тексты интерфейса — на английском, если ТЗ не говорит иначе.
6. Копирайты и лицензионные заголовки автора не трогать. Каждую законченную задачу добавь одной
   строкой в `FORK-CHANGES.md` (дата, что изменено, какие файлы).
7. Новые файлы `.cpp` в `src/` подхватываются глобом Android-сборки автоматически; для десктопа
   проверь, нужно ли добавить их в `CMakeLists.txt` (посмотри, как подключены соседние).

## Чем проверять себя
Компилятора на этой машине нет. Проверка компиляции — сборка в GitHub Actions после того, как
куратор запушит. Поэтому:
- перечитай каждый изменённый файл целиком: скобки, `#include`, объявления в `.h` совпадают с `.cpp`;
- для каждого вызова чужого API найди пример его использования в `src/` (укажи в отчёте, где нашёл);
- если ТЗ даёт Python-скрипт проверки или тесты — прогони их (`python ...`) и приложи вывод.
Не запускай adb, Android-устройство, Gradle и не пушь в git — это делает куратор.
