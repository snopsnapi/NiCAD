## Интерфейс
1. **Экструд / Push-Pull: модель нельзя вращать во время операции.**
   Причина в коде: `ExtrudeController::onViewportInput` (src/app/ExtrudeController.cpp:351) и
   аналог в `PushPullController.cpp:~675` захватывают ЛЮБОЕ нажатие во вьюпорте как тягу
   (сделано автором намеренно, жалоба «Steve: not letting me drag during extrude»).
   Хотим как во Fusion: тянуть только за стрелку, мимо стрелки — обычное вращение/пан.
   Образец уже в проекте: near-the-arrow hit-test в `EdgeOpController` (фаски/скругления),
   радиус попадания для пальца — `Gizmo.cpp:437`.
   **Сама стрелка тоже плохая — «немощная тонкая»**, поэтому автор и сделал весь экран ручкой.
   Сейчас (`Gizmo.cpp:36-46`): стержень радиусом 0.025 от длины, конус 0.08, зона попадания 0.04
   (×2.5 в touch mode) — на экране это пара пикселей. Нужна стрелка-ручка как во Fusion:
   толстая, с крупной «головкой» на конце, постоянного экранного размера (в dp, не от зума),
   зона попадания под палец (~48 dp), подсветка при касании, значение расстояния рядом с ней.
   Касание мимо ручки → обычное вращение/пан/зум.

1b. **Системный жест «Назад» = Undo.** Сейчас Back никак не обрабатывается: хинт
   `SDL_ANDROID_TRAP_BACK_BUTTON` не включён (`SDLActivity.java:725-739`), поэтому свайп от края
   уходит в Activity (сворачивает/закрывает приложение). Сделать: включить хинт, ловить
   `SDL_SCANCODE_AC_BACK`; если открыт диалог/идёт операция → отменить её (как Esc),
   иначе → Undo. Проверить predictive back на Android 16 (targetSdk, `OnBackInvokedCallback`).
   Предложено дополнительно: тап двумя пальцами = Undo, тремя = Redo (как в Procreate).
   **Решения пользователя:** Undo — свайп вдоль ПРАВОГО края; если отличить край сложно — можно
   оба края. Тап 2/3 пальцами для Undo/Redo — ок.
   Край различим: targetSdk 35, на Android 14+ `OnBackAnimationCallback` даёт
   `BackEvent.getSwipeEdge()` (EDGE_LEFT/EDGE_RIGHT); нужен `android:enableOnBackInvokedCallback`
   в манифесте. Левый край — ничего не делать (или тоже Undo как фолбэк).
   **Undo должен быть пошаговым внутри инструмента** (неправильная точка сплайна → откат одной
   точки). Механизм уже есть: в скетче каждое изменение пишется через `recordSketchMutation`,
   Backspace удаляет последнюю точку сплайна (`Application.cpp:~3437`), сплайн растёт по точке
   на снапшот (`Sketch.h:105`). Жест должен вызывать тот же контекстный Undo, что Ctrl+Z/Backspace:
   внутри инструмента — последний шаг инструмента, в скетче — последнее изменение скетча,
   снаружи — шаг истории.

1c. **Поворот двумя пальцами (twist) = вращение вида вокруг оси взгляда (roll).** Сейчас два пальца
   дают только пан (центроид) и зум (щипок): `Window::consumeTouchPan/consumeTouchZoom`
   (`Window.h:95`), применяются в `Application_Viewport.cpp:~3985`. Добавить в
   `Window::pollEvents` угол между пальцами → `consumeTouchRotate(float& dAngle)`, в камере —
   `roll(angle)` = поворот `m_up` вокруг (target - position) (`Camera.h`, `setUp` уже есть).
   Мёртвая зона на старте (~5–8°), чтобы щипок/пан не крутили вид случайно; после захвата
   крутить 1:1 вместе с паном и зумом (как в картах). Конфликт: режим «level orbit»
   (`setLevelOrbit`, Z всегда вверх) — в нём roll сбрасывается следующим орбитом; решить:
   либо twist переключает в свободную орбиту, либо в level-режиме twist отключён.

1d. **Центр вращения — точка на модели под пальцем, как во Fusion.** Сейчас
   (`Application_Viewport.cpp:3913-3970`): перепривязка центра орбиты к геометрии около ЦЕНТРА
   ЭКРАНА, раз на жест, и **только на десктопе** (`!touchMode()`); на планшете вращение идёт
   вокруг старого target, который мог «уехать» за модель. Сделать: в начале жеста — пик
   (`m_picker->pick`) точки под пальцем (для twist — под центроидом двух пальцев); промах →
   существующая логика колец вокруг центра экрана; совсем промах → старый target. Показывать
   маленький маркер центра вращения, пока идёт жест. Учесть ortho-ветку (берётся только глубина).

## Скетчи
2. **Математика сплайнов — не как во Fusion.** Сейчас: центростремительный Catmull-Rom
   (`Sketch.cpp:607` `catmullRomPoint`/`interpolate2D`) — только G1, кривизна скачет в каждой точке;
   в геометрию идёт пересэмплирование в float + `GeomAPI_PointsToBSpline` степени до 8
   (`Sketch.cpp:~1406`, `~2230`) — приближение приближения, тяжёлый NURBS. Нет касательных на
   концах/в точках, нет режима по CV. Цель: два типа как во Fusion — fit-point (C2 кубика,
   `GeomAPI_Interpolate`, касательные) и control-point (`Geom_BSplineCurve`, степень 3/5);
   точная кривая в OCCT без пересэмплирования.
   **Решения пользователя:** совместимость со старыми проектами НЕ нужна — Catmull-Rom выкидываем
   целиком. Ручек касательных («пивотов») НЕ делать — во Fusion ими почти не пользуется, портят
   кривизну. Т.е. главный тип — fit-point C2 без ручек.
   **Control point spline — нужен (на будущее, после fit-point):** как во Fusion на скрине
   пользователя — CV-точки с пунктирным управляющим многоугольником, кривая — точный
   `Geom_BSplineCurve` (clamped, равномерные узлы), **выбор степени** в свойствах сплайна
   (Fusion: 3 и 5; у нас можно 2–7, ограничение: степень < числа CV), смена степени на уже
   построенном сплайне. Тянуть CV пальцем — кривая обновляется сразу.
   **Гребёнка кривизны (Curvature Comb)** — переключатель для выбранного сплайна (для обоих типов).
   Формат проекта (.mzr): свой текстовый формат, скетч построчно (`S id constr n ids...`,
   `ProjectIO.cpp:332/753`), тела — бинарный OCCT BREP (BinTools).
2a. **Замыкание сплайна:** удобное взаимодействие — при подводе к первой точке магнит +
   подсветка кольцом, тап по первой точке = замкнуть и завершить.
2b. **Быстрое редактирование сплайна:** тянуть точки прямо пальцем, без входа в режимы, без ручек.
2c. **Лёгкая заливка всех замкнутых контуров как во Fusion.** Сейчас заливка только у
   наведённого/выбранного региона (`Application_Viewport.cpp:~1185` highlightRegion);
   инфраструктура есть (`buildRegions`, фоновый `m_regionWorker`) — рисовать все регионы
   скетча с малой альфой.
2d. **Линии тонкие для тача.** Толщины заданы в физических пикселях (`glLineWidth(1.0..2.5)`,
   SketchRenderer/EdgeRenderer и др.), без учёта плотности экрана (у планшета 440 dpi → линия
   ~0.1 мм). Нужно: толщина в dp; т.к. широкие `GL_LINES` в GLES не гарантированы — линии
   квадами (расширение в шейдере). GPU планшета: Adreno 732, GLES 3.2.
3. **Сплайн-инструмент:** после каждой точки не предлагать следующую — убрать жёлтый
   предполагаемый сегмент; привязки на сплайне по умолчанию выключить; явная кнопка «Готово».
4. **Точки скетча мелкие** — размер и зона касания в dp под палец.
5. **Двойной тап по скетчу** → открыть на редактирование.
6. **3D-скетчи** — нет совсем (модель скетча плоская, `glm::vec2`). Новая сущность; для реверса —
   кривые по скану в пространстве. После нормальных сплайнов, на той же математике.

## Моделирование
7. **Offset Face как во Fusion.** Сейчас есть Push/Pull (`PushPullOp.cpp`): выдавливает призму из
   контура грани и делает boolean — вокруг грани остаётся «ступенька», соседние скругления/фаски
   остаются на месте, грань только плоская. Нужно: грань (в т.ч. кривая) сдвигается по нормали,
   **соседние грани продлеваются/подрезаются** до неё — OCCT `BRepOffset_MakeOffset` с
   `SetOffsetOnFace(face, d)` (остальные 0, `GeomAbs_Intersection`), несколько граней сразу.
   **Фаски/скругления, примыкающие к грани, при выдавливании вперёд удаляются** (пожелание
   пользователя): найти соседние blend-грани и снести их `BRepAlgoAPI_Defeaturing` перед офсетом —
   готовый `DefeatureOp.cpp` («Remove Feature») уже есть. Распознавания фасок/скруглений нет
   (`BlendCut.h` их только строит) — написать: соседняя грань = скругление, если цилиндр/тор/
   B-сплайн, касательный к обеим соседям; фаска — узкая плоская полоса между двумя гранями.
   Опция «Remove adjacent fillets/chamfers» (по умолчанию вкл. при положительном сдвиге).
   UX: стрелка-ручка по нормали (пункт 1), значение рядом, живой предпросмотр.
   Для проверки геометрии без планшета нужен Linux-job в CI с тестами `src/modeling` (сейчас нет).

GUI (Qt/Coin, `*_gui.py`, ~3.6k строк) НЕ переносится — переписывать под ImGui/тач, но поведение
(привязки, двойной клик = редактирование, Ctrl+Z внутри инструмента) брать как спецификацию.

| Модуль | Что | Перенос в C++ |
|---|---|---|
| `rt_spline.py` (228) | 3D-сплайн через точки: хордовая параметризация, степень, замкнутый (периодический), G0/G1/G2 к другим кривым, G1 magnitude; коллокационная матрица с усреднёнными узлами | scipy `BSpline` → `BSplCLib::EvalBsplineBasis`, `np.linalg.solve` → `math_Gauss`, `Part.BSplineCurve` → `Geom_BSplineCurve`, периодический → `GeomAPI_Interpolate` |
| `rt_curvature.py` (193) | Кривизна по мешу скана, раскраска | циклы вместо scipy.sparse |
| `rt_surface.py` (340) | Fit Surface по зоне скана (МНК с гладкостью), X-Form, extend, resample | нужен разреженный МНК → Eigen (header-only) |
| `rt_skin.py` (465) | Loft с рельсами, Coons/Patch, network | OCCT + своя математика |

Порядок: сначала `rt_spline` — им же закрываем пункт 2 (fit-point сплайн для 2D-скетчей: та же
функция `interpolate`, в 2D z=0, выбор степени). Затем 3D-сплайн / 3D-скетч.
**Проверка переноса — золотые тесты:** прогнать Python-версию (FreeCADCmd, у него есть numpy/scipy)
на наборах входов → JSON с полюсами/узлами/точками → C++ тест сравнивает с допуском. Идеально для Kimi.

**Поведение Studio Spline, которое переносим (`rt_spline_gui.py`):**
- **Сплайн хранит не геометрию, а определяющие точки** (`PointData` JSON: позиция, тип привязки,
  ссылка на кривую + параметр u / конец, G0–G2, reverse, magnitude) и перестраивается из них.
  Поэтому он всегда редактируем, а точки, привязанные к кривой, **ассоциативны** — поменялась
  исходная кривая → после пересчёта точка едет за ней. В materializr: сплайн = операция истории,
  точки — в её params-блобе (`Operation::serializeParams`); ссылки на рёбра — через их слой
  топологических имён.
- **Двойной клик по сплайну во вьюпорте → снова открыть редактор** (`ViewProviderSpline.doubleClicked`).
- **Привязки по приоритету** (`_snap`): End (конец ребра) → On Curve (ближайшая точка ребра к лучу,
  запоминается u) → On Mesh (ближайший треугольник скана на луче, `nearestFacetOnRay`) → Free
  (плоскость, параллельная экрану, через глубину предыдущей точки). Радиус пика 11 px → у нас в dp.
  Маркер типа привязки у курсора.
- Тап по самой кривой между точками → **вставить точку** туда; перетаскивание точки; undo-шаг
  пишется, только если точка реально сдвинулась; подсветка при наведении.
- Меню точки: Delete, G0/G1/G2 (всплывашка), Reverse, Magnitude. Undo/Redo внутри инструмента (100 шагов).

**Чего нет в materializr для реверса:** скан как опорный меш (`RefMeshImport`) — только для показа,
**намеренно не пикается** (`RefMeshImport.h`). Для «On Mesh» привязки 3D-сплайна нужен пик по мешу:
BVH по треугольникам + луч. Альтернатива — `StlIO::import` (скан → B-rep), но для плотных сканов тяжело.
