# ТЗ-08. Тач-навигация: поворот двумя пальцами (twist) + центр вращения под пальцем

## Цель (пожелания пользователя, BACKLOG.md пп. 1c, 1d)
1. Поворачиваешь два пальца на экране — модель поворачивается вокруг оси взгляда (roll), вслед за пальцами.
2. Вращение одним пальцем идёт вокруг точки модели ПОД пальцем (как во Fusion), а не вокруг старого target.

Только режим касаний (`touchMode()`); десктоп не меняется.

## 1. Распознавание twist — `src/app/Window.cpp` / `Window.h`
Сейчас (Window.cpp ~491–580) два пальца: `m_twoFingerMode` 0 = не решено, 1 = pan, 2 = zoom; решение по
NET-изменению с начала жеста (`panNet`, `zoomNet`), накопители `m_panAccX/Y`, `m_zoomAcc`, выдача через
`consumeTouchPan` / `consumeTouchZoom` (Window.h:95–96). Добавь третий режим по тому же принципу:
- угол пары: `ang = atan2(sy, sx)`; в начале жеста запомни `m_startPinchAngle`, `m_lastPinchAngle`;
  разницу углов всегда приводи в (−π, π];
- `twistNet = |ang − m_startPinchAngle|`, «дуговая длина» `twistArc = twistNet * dist * 0.5f` (пиксели — сравнимо с panNet/zoomNet);
- в недорешённом состоянии: `if (twistNet > 8° && twistArc > panNet * 1.2f && twistArc > zoomNet * 1.2f) m_twoFingerMode = 3;`
  (проверять ДО проверок pan/zoom, чтобы явный поворот не уходил в pan);
- в режиме 3 копи `m_twistAcc += dAng` (радианы, знак — по часовой/против как на экране);
- `bool consumeTouchTwist(float& dAngle);` — по образцу `consumeTouchZoom` (вернуть и обнулить);
- при пересчёте пары (палец поднят, ≥2 остались — ветка re-anchor) обнови и углы;
- учти `m_sessionPanNet/ZoomNet` (детект мульти-тапа): добавь `m_sessionTwistNet` и там, где тап отменяется
  при движении, учитывай и его (найди, где читаются `m_sessionPanNet`).

## 2. Камера — `src/viewport/Camera.{h,cpp}`
`void roll(float radians);` — поворот вида вокруг оси взгляда (target − position) через target: поворачивается
только `m_up` (позиция и target не меняются). `finishAnimation()` в начале, как в `orbit()`.
Режим level orbit (`m_levelOrbit`, по умолчанию ВКЛ в настройках, Settings.h:82): там орбита держит «верх» по
`m_levelAxis`. Сделай так, чтобы roll в level-режиме поворачивал и `m_levelAxis` тем же поворотом (вид остаётся
наклонённым, дальнейшая орбита крутит вокруг наклонённой оси). Прочитай `orbitLevel` и проверь, что это так
работает; если `m_levelAxis` используется иначе — опиши в отчёте и сделай минимально корректно.

## 3. Применение — `src/app/Application_Viewport.cpp`
Рядом с применением `consumeTouchZoom` (~строка 4030, блок «Two-finger touch gestures»):
```cpp
float tdr = 0.0f;
if (!gizmoOwnsDrag && m_window->consumeTouchTwist(tdr) && std::fabs(tdr) > 1e-4f)
    cam.roll(tdr);   // знак подбери так, чтобы модель поворачивалась ВМЕСТЕ с пальцами
```
Центр twist: в начале жеста twist (первый кадр режима 3) — пик точки модели под центроидом пальцев
(как делается для пана: `m_picker->pick(...)`, см. блок пана рядом) и, если попали, `cam.setTarget(hit)` ДО roll.

## 4. Центр орбиты под пальцем — тот же файл, ~строки 3913–3970
Сейчас перепривязка центра орбиты (`m_orbitAnchorHeld`, пик вокруг ЦЕНТРА экрана, кольца радиусов 40/85/150)
выполняется только `if (!materializr::touchMode() ...)`. Для touch сделай: в начале одно-пальцевой орбиты пик в
точке касания (`ImGui::GetMousePos()` минус `ImGui::GetItemRectMin()` → координаты вьюпорта, как в соседнем коде);
попал — `cam.setTarget(hit)` (с той же ortho-веткой «берём только глубину», что уже есть); промах — существующая
логика колец вокруг центра экрана; совсем промах — target не трогать. Десктопное поведение не менять.

## Ограничения
- Не меняй пороги pan/zoom. Только добавляешь twist.
- Строка в `FORK-CHANGES.md`.

## Самопроверка
Перечитай; в отчёте — как приведена разница углов к (−π, π], где обновляются углы при re-anchor, какой знак roll.

## Критерии приёмки (пользователь на планшете — adb мультитач не умеет)
- Поворот двух пальцев крутит модель вокруг оси взгляда; щипок по-прежнему зумит, сдвиг двух пальцев — панорамирует.
- Вращение одним пальцем крутит вокруг точки под пальцем.
